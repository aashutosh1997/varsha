# Varsha — iOS Workout App

A SwiftUI iOS app that runs a structured workout session with timed/rep-based sets, automatic progression, screen-always-on, and embedded form-demonstration media (MP4 video, animated GIF, or two-frame fallback). Built around a PCOS-tailored training plan.

## Tech Stack

| Layer | Choice | Why |
|---|---|---|
| Language | Swift 5.9+ | Modern concurrency, observation |
| UI | SwiftUI (iOS 17+) | Reactive UI, less boilerplate, `@Observable` |
| State | `ObservableObject` + `@Published` | Battle-tested, Combine integration |
| Persistence (later) | SwiftData | Native Codable, less ceremony than CoreData |
| Video | `AVKit` / `AVPlayer` | Native, low overhead |
| Audio cues | `AudioServicesPlaySystemSound` + `UINotificationFeedbackGenerator` | No extra deps |
| Health (later) | HealthKit | Log workouts, calories |

## Core Design Decisions

### 1. Flatten the workout into a linear set sequence

A workout is a tree (Workout → Blocks → Exercises × Sets), but a runner needs a *list*. The session manager flattens everything into `[PrescribedSet]` in execution order — including superset interleaving (A1, A2, A1, A2, A1, A2 …) and circuit unrolling (Round 1 ex1-ex2-ex3, Round 2 ex1-ex2-ex3 …). The UI just walks `currentSetIndex` 0 → N.

### 2. Two set types, one interface

A set is either **rep-based** (user taps "Done" when finished) or **time-based** (auto-completes when countdown hits zero). Same `PrescribedSet` model — it has both `reps: Int?` and `durationSeconds: Int?`; whichever is non-nil drives behavior. HIIT intervals just become time-based sets.

### 3. State machine, not a pile of booleans

```
.notStarted  →  .performing(setIndex)  →  .resting(setIndex, secs)  →  .performing(setIndex+1) … →  .completed
```

Reset/skip transitions are explicit. No "if isResting && !isPaused && hasStarted" tangles.

### 4. Reset granularity

The user said "option to reset once it has started." Two resets, both wired:
- **Reset current set** — clears the timer, restarts the current set (mistake recovery).
- **Reset workout** — back to set 0. Confirmation prompt (destructive).

### 5. Media: progressive fallback

```
Exercise.videoURL             →  set?                    AVPlayer (looped, muted)
        ↓ no
Bundle: ExerciseMedia/{id}.gif                           AnimatedGIFView (ExerciseDB)
        ↓ no
Bundle: ExerciseMedia/{id}-0.jpg
       + ExerciseMedia/{id}-1.jpg                        TwoFrameAnimator (free-exercise-db)
        ↓ no
Exercise.staticImageName      →  set?                    Static image
        ↓ no
Exercise.formCues             →  always present          Icon + bullets
```

The `ExerciseMediaView` makes this transparent to its parent.

### 6. Keep screen awake

```swift
UIApplication.shared.isIdleTimerDisabled = true
```

Wrapped in a SwiftUI `ViewModifier` so it auto-toggles on view appear/disappear. Critical: re-enable on disappear or you'll drain the user's battery.

## Exercise Media — Offline Bundling

Two sources, in priority order. The fetcher tries each; whatever it gets per exercise is what the app uses.

| Source | License | Format | Coverage in this plan |
|---|---|---|---|
| **[ExerciseDB v1](https://docs.ascendapi.com/products/edb-v1/overview)** (free hosted, no auth) | AGPL-3.0 | 180p animated GIF | Most exercises |
| [yuhonas/free-exercise-db](https://github.com/yuhonas/free-exercise-db) | Public Domain (Unlicense) | Two static JPEGs (start + end) | Fallback for anything EDB misses |

### Workflow

1. **Fetch all media** (one-time, ~10–30 MB):
   ```bash
   cd Varsha
   python3 Scripts/fetch_exercise_media.py
   ```
   The script paginates through ExerciseDB's free API (`https://oss.exercisedb.dev/api/v1/exercises`), matches each Varsha exercise by name candidates, downloads the GIF if found, and falls back to the free-exercise-db start/end photos for any exercise without an EDB match. Idempotent — re-running won't redownload existing files.

   The script writes `Resources/ExerciseMedia/{id}.gif` (or `{id}-0.jpg` + `{id}-1.jpg` when falling back), plus a `manifest.json` documenting source per exercise.

   **Flags:** `--gifs-only` skips the fallback (AGPL-only build), `--frames-only` skips ExerciseDB entirely (public-domain-only build, see License section below).

2. **Add to Xcode** — drag `Resources/ExerciseMedia/` from Finder into the Xcode project navigator (drop it inside your `Varsha` target's source group).

   The exact behavior depends on your Xcode version:

   - **Xcode 16+** — the "Create folder references" radio button is gone. Apple replaced it with **synchronized folders** as the default. Drop the folder in and it'll appear blue automatically. No dialog options to choose. If the dialog does appear, just check "Copy items if needed" and click Add — that's it.

   - **Xcode 15 or earlier** — the dialog has the old radio buttons. Pick **"Create folder references"** (not "Create groups"). The folder shows blue.

   In both cases, the result should be a **blue folder** named `ExerciseMedia` in the navigator. If yours is yellow (a group), the subdirectory won't survive into the bundle — but the lookup code in `ExerciseFrameLocator` falls back to the bundle root, so files added as a group will still work as long as they're inside the target's "Copy Bundle Resources" build phase.

3. **Verify it built correctly** — Product → Build, then Product → Show Build Folder in Finder → `Products/…/Varsha.app` → right-click → Show Package Contents. You should see either an `ExerciseMedia/` subfolder containing the GIFs, or the GIFs at the bundle root. Either is fine.

4. **That's it.** `ExerciseMediaView` automatically prefers GIFs over the two-frame animator.

### Per-exercise overrides

To upgrade a specific exercise to higher fidelity, set the appropriate field on the `Exercise` in `WorkoutData.swift` — no other code changes:

| Field | Effect |
|---|---|
| `videoURLString: "..."` | Self-recorded video wins over GIF |
| Bundled `back-squat.gif` exists | Animated GIF (default for matched exercises) |
| Bundled `back-squat-0.jpg` + `back-squat-1.jpg` exist | Two-frame animator (fallback) |
| `staticImageName: "..."` | Single static image |
| None of the above | Icon + form cues |

### Recommended upgrades (do these manually)

The 6–8 most heavily-loaded compounds deserve a hand-recorded video. 5-second side-angle loops, silent, no editing needed.

- Back Squat (`back-squat`)
- Romanian Deadlift (`rdl`)
- Bench Press (`bench-press`)
- Barbell Row (`barbell-row`)
- Overhead Press (`ohp`)
- Hip Thrust (`hip-thrust`)
- Bulgarian Split Squat (`bulgarian-split-squat`)
- Pull-up / Lat Pulldown (`assisted-pullup`)

Drop the MP4s in the bundle and update `videoURLString` to `bundle://filename.mp4` (or use a real CDN URL).

## Critical iOS Specifics

### Timer correctness
`Timer.scheduledTimer` runs on the main runloop and pauses during scrolling on the default mode. Use `.common` runloop mode, or use a `DispatchSourceTimer`, or use `Task.sleep` in async context. The session manager uses `Timer` with `RunLoop.main.add(timer, forMode: .common)` — see code.

### Background behavior
By default, when the app backgrounds, the timer stops. Two options:
1. **Accept it.** The user said "remains open during the workout" — keep the screen on, problem solved.
2. **Continue in background** — requires `audio` background mode + a silent looping audio track. More complex, do later.

### Haptic + audio cues
Last 3 seconds of rest: tick haptic each second. Set complete: success haptic. Rest end: notification haptic. All free, no permissions.

## Xcode-side Rename (one-time)

Renaming the source files isn't enough — Xcode and iOS use the bundle identity for the home-screen icon label, App Store name, and code signing. Do all of these once:

1. **Project name.** Open `.xcodeproj` → click the project root in the navigator → in the Identity inspector, rename the project to `Varsha`. Xcode will offer to rename related items — accept all.
2. **Display name (what shows under the icon).** Target → General → "Display Name" → `Varsha`. This is `CFBundleDisplayName` in Info.plist.
3. **Bundle identifier.** Target → General → "Bundle Identifier" → e.g. `com.yourname.varsha`. Lowercase, reverse-DNS.
4. **Scheme.** Product → Scheme → Manage Schemes → rename the scheme to `Varsha`.
5. **App icon.** Drop a 1024×1024 icon in `Assets.xcassets/AppIcon`. Until then it'll use the SwiftUI default.
6. **Launch screen.** Optional but nice — add a `LaunchScreen.storyboard` or use the SwiftUI launch screen Info.plist key with the Varsha brand color.

After all of that, `Cmd+B` should build clean and the simulator's home screen should show "Varsha" under the icon.
